# 声音、质检、交付

## 声音

片子没有人声，声音只有两样：配乐和音效。全部由 `scripts/score.py` 用代码合成，和画面读同一份时间轴，所以改了剧本重跑一遍就对得上。

### 配乐

在 `film.ts` 的 `music` 里选一个 `mood`，其余自动：

| mood | 听起来 | 配什么题 |
|---|---|---|
| `wonder` | 好奇、开阔，慢慢变大 | 自然、宇宙、地理、「原来是这样」 |
| `warm` | 温暖、柔和 | 人、身体、生活 |
| `tense` | 小调、悬着 | 危险、谜题、反常、「出事了」 |
| `bright` | 轻快 | 小窍门、日常现象、轻松的题 |
| `calm` | 安静、没有鼓 | 沉思、情绪、慢的题 |

音乐的段落跟着章节走：每换一个 `chapter`，和弦从头开始，小节线落在换章那一帧。整体强度从开头往 3/4 处一路升，最后收回来。
`bpm`、`drums`、`seed`（换一版旋律）可以再调。

### 音效

写在剧本每个场景的 `sfx` 里，`at` 写帧号或者 `'L1'`（第 2 句字幕出现时）、`'L1+12'`。`len` 的单位是帧。

| kind | 声音 | 放在哪 |
|---|---|---|
| `whoosh` | 气流扫过 | 大的移动、镜头甩过去（叠化处自动有一声轻的，不用写） |
| `tick` / `click` | 轻的一下 | 一个标注出现、一个点亮起 |
| `pop` | 弹出 | 一个东西冒出来 |
| `count` | 一串快的滴答 | 数字在滚，`len` 和滚动一样长 |
| `chime` | 一声铃 | 答案、关键数字落定 |
| `shimmer` | 一串亮的铃 | 开头第一帧、一个惊艳的揭晓 |
| `thud` | 闷响 | 东西落地、塌下来、重的结论 |
| `drop` | 低沉的下坠 | 转折落地的那一下 |
| `riser` | 往上升 | 揭晓之前蓄力，`len` 是蓄多久，在 `at` 那一刻到顶 |
| `swell` | 一阵上扬的风 | 场景要打开、变大之前 |
| `paper` | 翻纸 | 出处卡片滑进来 |
| `hush` | 不是声音 | 让音乐在 `len` 帧里退下去，揭晓落在安静里 |

- 第 0 帧要有声音（`shimmer` 或者 `whoosh`），不然刷到时像坏了。
- 音效跟着画面里看得见的动作走，不跟着字幕走。一个场景两三个就够，多了吵。
- 一个揭晓的标准写法：`riser`（蓄力）→ `hush`（安静）→ 揭晓那一帧 `drop` 或 `chime`。示范片的「河抄了近路」就是这样。

`npm run audio` 合成配乐、调到 -14 LUFS、真峰值 -1.5 dBTP（短视频平台的标准响度），写到 `public/audio.wav`。

## 质检

能交给机器查的都交给机器，人只看机器看不出来的。

1. **`npm run qa`**：每 6 帧把屏上的字量一遍：字太小、贴边、压在字幕上、两段字叠在一起。按场景和帧号列出来，写到 `out/qa.txt`。
   故意的装饰性小字（比如尺子上密密的刻度）加 `data-qa="skip"`；本来就是一体的一组字（比如里程表的一列列数字）外面加 `data-qa="one"`。
2. **`npm run check`**（渲完成片后）：规格（1920×1080、30 帧、H.264、有声音）、第一帧不能是黑的、头 1.5 秒画面要有明显变化、中间不能闪黑、连续 3 秒不动、
   响度和峰值、开头有没有声音。同时出一张每 2 秒一格的联系表 `out/check.jpg`，按手机屏的大小排。
3. **自己看**：打开 `out/check.jpg` 从左到右看一遍，再关掉声音看一遍成片。逐条问：
   - 每一格，不看字幕，知道在演什么吗？
   - 主体够大吗？有没有哪一格画面空、乱、像课件？大数字、标注有没有压在主体上？
   - 颜色读得对吗？变热的看着在变热，没有因为配色看成变凉、变少
   - 每一格和前一格比，有没有新的东西发生？
   - 第一格就能让人停下来吗？
   - 每个说法对得上 `brief.md` 的事实表吗？

   发现问题只改那几个场景，渲几张静帧确认，再重渲：场景长短没变时用 `node scripts/render.mjs --patch 起-止` 只渲那一段拼回去
   （帧号看 `npm run cues` 列的场景表）；长短变了就整片重渲。

渲染很占内存和时间：一台机器同时只跑一个渲染；渲整片之前先用静帧把问题都改掉。
只改了声音时用 `node scripts/render.mjs --remux`，不用重渲画面。

## 封面

`npm run covers` 渲 `src/film/Cover.tsx`，出 16:9、4:3、3:4 三张到 `out/`。横版视频上传用 16:9；个人主页会把封面裁成竖的，
所以主体和大字放在中间，3:4 那张里也要完整。封面大字就是片名问题，下面一行小字放最抓人的那个数。

## 交付

给用户的东西：

- 成片 `out/film.mp4`（高画质，直接上传用）。用户要在手机上预览，另外压一份小的：
  `ffmpeg -i out/film.mp4 -c:v libx264 -b:v 2M -c:a aac -b:a 128k out/film_预览.mp4`。
- 三张封面。
- 标题（就是那个问题，20 字以内）和简介（一两句话说这条讲了什么，下面列出处）。
- 片长、自查结果、自己觉得还不够好的地方。

提醒用户：上传时勾选平台的「内容由 AI 生成」标识；简介里的出处保留。

## 返修

用户提意见时：

- 先确认意见指的是哪个场景、哪一秒（`npm run cues` 打出的表里有每句的帧号）。
- 讲法的问题（看不懂、跑题、开头不抓人）回到 `brief.md` 和剧本改，不要只在画面上修修补补。
- 画面的问题只改那个场景，渲那几秒的静帧给自己看过，再用 `--patch` 补渲那一段（长短变了就整片渲）。
- 改完把这一轮改了什么、在第几秒，一条条告诉用户。
