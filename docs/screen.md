# 画面：怎么让画面自己把事讲清楚，而且好看

## 画面是主角

把字幕全部遮住，只看画面，一个没背景的人能不能说出发生了什么？这是唯一的标准。
字幕只负责给画面里正在发生的事起个名字、点一下意思。

所以每个场景先想：**这一步，在画面上是什么东西发生了什么变化？** 水被甩到外侧——那就让观众看见最亮最快的那股水流从中间滑到外侧；
岸被掏空——那就把河切开，看见岸底下被挖进去、一块块塌下来。想不出这个变化，就是还没想清楚怎么讲。

## 像真的

观众一眼就分得出「真东西」和「示意图」。示意图像课件，真东西像纪录片。

- **用真数据。** 地方用真实卫星影像（`Satellite`）、真实地形（`Terrain`，从高程数据算出山体阴影和河网）和地球（`Globe`）；数字用真实数据或自己算出来的；
  过程用模拟（`Flow` 的速度场、`Choreo` 一步步演算）。真数据画出来的细节是编不出来的。
- **东西要有体积和质感**：渐变、明暗、投影、纹理、高光。平涂的色块和细线框看起来像图标。
  示范片里河有深浅（中间深、岸边浅）、有沙洲、有岸边的树和水面的反光；剖面的土有分层和颗粒。
- **比例要对。** 人是人的比例，东西之间的大小关系符合真实。
- **不用 emoji、图标库、剪贴画、简笔画。** 需要一个东西就用 SVG 把它认真画出来，画到放大到半个屏也经得起看。
- 真照片、档案图、卫星图更有说服力，但只用能公开使用的（公有领域、CC 协议），作者和协议写进 `Photo` 的 `credit`。

## 一个场景是一个世界

- 每个场景在 1920×1080 的坐标里画一个完整的「世界」（套在 `World` 里），讲下一句时**动镜头、加东西**，而不是换一张新图。
  `camAt(f, [[帧, {x, y, z}], …])` 给镜头写关键帧，起步和停下都是缓的。
- **场景和场景之间接得上。** 上一个场景最后镜头停在哪，下一个场景就从相似的位置、相似的东西开始。示范片从太空落到黄河，
  再从地形里那道弯转到俯视的一段河，再把这段河横着切开，观众始终知道自己在看哪。
- **主体要大。** 手机上看，要讲的那个东西至少占画面高度的三分之一；要看清的细节，镜头推上去。
- 画面分前、中、后三层：后面是氛围（引擎已经铺好：底色、光、虚化光斑、颗粒、暗角），中间是主体，前面是标注。
  远处的层用 `World` 的 `depth` 小于 1，镜头一动就有视差，画面立刻有了纵深。

## 一直在动，但动得有理由

- **没有哪个画面能静止超过 3 秒。** 引擎给每个场景都加了极慢的推镜，但这不够：每 2–3 秒画面里要发生一件新事（一个东西画出来、一个数字滚动、镜头推近、粒子在流）。`npm run check` 会抓连续 3 秒不动的地方。
- **东西出场要有过程**：线是画出来的，数字是滚上去的，一组东西是依次出来的（`stagger`），不要一下子全部出现。
- **关键的数字和比较，要变成眼睛看得见的东西**：弯弯的河揭下来拉直，放在直线旁边比长短；三条队并排快进跑一千次，每次给赢的那条亮一下；
  一粒饭里的水倒出来装进量杯。只在图上叠一个数字，观众记不住；亲眼看到「长了一倍」，这一帧往往就是全片最想截图的画面。
- 进场用 `ease.out3`（快进慢收），镜头和位移用 `ease.inOut2/3`，落定的那一下可以用 `ease.back`。不要匀速。
- 「持续存在」的动：水在流、光在呼吸、粒子在漂，让静下来的画面也是活的。
- 动的东西是观众要看的东西。不要为了动而让无关的装饰乱飞，抢走注意力。

## 字和标注

- 字幕 64 像素（引擎定好了）。画面里关键的字至少 44 像素（`SIZE.key`），次要的 34（`SIZE.label`），任何字都不小于 28（`SIZE.min`）。
- 字离画面边缘至少 24 像素；底部字幕区（下面约 300 像素）在有字幕时不要放别的字。
- 标注贴着它说的那个东西：`Tag` 是一个点、一根引线、一段字，比飘在空中的字清楚。
- 画面里的字是给眼睛扫一下的：两三个字到一个短语，不写句子。
- `npm run qa` 会把字太小、贴边、压字幕、两段字叠在一起的地方按场景和帧号列出来。

## 颜色

每种颜色全片只表示一种意思，观众看几次就会自己认出来。

- `accent`（强调色）：答案、主角、关键的那个东西。一个画面里只给最重要的一样东西。
- `accent2`（第二强调）：对照、反面、警示、「被冲掉的」「错的」。
- `water`：水。`ramp`：从低到高的五级色阶，地形海拔、密度都用它。
- 冷和热用 `heat(0…1)`（`look.ts` 里的温度色阶，冷蓝到热红，四种外观通用），不要拿 `accent2` 或 `water` 去表示冷。
- 其余全部用 `ink` / `dim` / `faint` 这些中性色。画面上除了中性色，同时出现的颜色不超过三种。

## 转场

- 场景之间默认叠化（20 帧）。要更慢更柔的接法，加大 `xf`。
- 一个揭晓、一个转折，用 `enter: 'flash'`（一下白闪）。`cut`（硬切）只在节奏要猛的时候偶尔用。
- **不要闪黑、压黑再亮起来。** 这类片子的场景之间应该像一个连续的世界，黑场会让观众以为片子结束了。
- 最好的转场是镜头运动本身：推近一个东西，推到底就是下一个场景。

## 人

- 讲人的事（情绪、选择、排队、社交）就画人，用 `Figure` / `People`：真人比例、有明暗，表情按眉眼嘴分开画。
- 表情必须和这一句讲的情绪一致：担心就是担心，不能读起来像在笑。做完放大看一眼脸。
- 人在画面里要有事做（指着、抬手、转头、走动），站成一排不动的人最无聊。
- 只是为了数数时（1000 个人里有几个），用 `Crowd` 的点或小人。

## 外观

四套外观，整片只改 `film.ts` 里一行，所有组件跟着换颜色、字体和质感。按题材的情绪挑：

| 外观 | 样子 | 适合 |
|---|---|---|
| `ink` 墨金 | 暖黑底、象牙白宋体、香槟金强调、胶片颗粒 | 自然、地理、历史、宇宙、经济、概率 |
| `night` 夜蓝 | 靛蓝夜空、月白楷体、珊瑚红强调 | 人、心理、关系、故事、社会现象 |
| `lab` 信号 | 石墨底、骨白黑体、荧光黄绿强调、等宽数字 | AI、计算机、算法、数据、工程 |
| `paper` 纸本 | 暖白纸、墨黑宋体、朱红强调、浅投影 | 身体、日常科学、东西是怎么工作的、生活方法 |

外观管的是底色和字；画面里东西本身的颜色（土是土色、水是水色、皮肤是皮肤色）按真实来，只有强调用外观的颜色。
题材和画面冲突时听画面的：主角会发光（光、波、电、火、热像、屏幕、星空）就用深底，浅底上发光是灰的。

## 写代码时的规矩

Remotion 是一帧一帧截图的，每一帧都要能单独、确定地算出来：

- 画面只由帧号决定。不用 `Math.random()`、`Date.now()`、CSS 动画和 transition、`setTimeout`；要随机就用 `hash(种子)` 和 `noise`。
- 场景里用 `useScene()` 拿到场景内帧号 `f` 和 `cue(i)`（第 i 句字幕出现的帧）。动画的时间点写成 `cue(1) + 10` 这样，改了字幕会自己跟着走，不要写死绝对帧号。
- 读 `public/` 里的数据用 `useData('路径')`，图片用 `<Img src={staticFile('路径')} />`，它们都会让渲染等数据到了再出帧。
- 中文字体由引擎按全片用到的字预先加载好（渲染时自动扫 `src/`）。屏上的字写在 `src/` 以外的文件里时，要把目录加进 `scripts/glyphs.mjs`。
- SVG 里的 `id`（渐变、遮罩、滤镜）全片唯一，用场景名做前缀，否则两个场景叠化时会互相串。
- 粒子和点阵上千个时，用一个 `<canvas>` 画（`Flow` 就是这样），不要生成上千个 DOM 元素。
- 改完一个场景先渲几张静帧看（`node scripts/stills.mjs`），不要每次都渲整片。
